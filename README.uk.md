# Snyk Desk

[English version](README.md)

Невеликий нативний застосунок для macOS, який запускає [Snyk CLI](https://docs.snyk.io/snyk-cli) для ваших локальних репозиторіїв, зберігає результати і показує їх в одному місці. Працює з будь-яким репозиторієм на диску, де б він не хостився (GitHub, Bitbucket Server, GitLab або ніде).

> Snyk Desk - незалежний проєкт з відкритим кодом. Він не пов'язаний із Snyk Ltd., не схвалений і не спонсорований нею. "Snyk" є торговельною маркою Snyk Ltd.

## Можливості

- **Покрокове налаштування**: вибір папки для запускача сканів (наявний запускач розпізнається і зберігається), встановлення Snyk CLI з прогрес-баром або виявлення вже встановленого, вибір папок з репозиторіями, встановлення потрібних їм інструментів збірки, вхід у Snyk.
- **Інструменти збірки без Terminal**: застосунок дивиться на ваші репозиторії (`pom.xml`, `build.gradle`, `package.json`, `go.mod`, файли Python і Swift), показує, які з Java, Maven, Gradle, Node.js, Go і Xcode Command Line Tools їм потрібні, і встановлює відсутні однією кнопкою з прогрес-баром. Завантаження йде з офіційних сайтів у власну папку застосунку, без пароля адміністратора і без Homebrew.
- **Проєкти з кількома репозиторіями**: кожен репозиторій належить до проєкту, назва якого визначається за шляхом (`.../acme/repos/api` належить до `acme`) і її можна змінити. Дашборд і вкладка Projects згруповані за проєктами, проєкт можна просканувати цілком.
- **Дашборд**: підсумок за серйозністю по всіх репозиторіях і по кожному проєкту, картка для кожного репозиторію з останнім сканом, порожній стан до першого скану.
- **Проєкти**: запуск одного репозиторію окремо, прогрес і лог, історія сканів, фільтр знахідок за типом (залежності чи код) і серйозністю. Для кожної знахідки видно пакет або файл, шлях залежності і версію з виправленням, якщо вона є.
- **Перемикачі для кожного репозиторію**: скан залежностей (`snyk test`), скан коду (`snyk code test`) і знімок у ваш дашборд Snyk (`snyk monitor`).
- **Результати там, де вам треба**: за замовчуванням скани зберігаються поруч із запускачем у вигляді `<проєкт>/<репозиторій>/<дата-час>`. Для будь-якого репозиторію можна вибрати свою папку, наприклад у папці проєкту цього клієнта.
- **Розклад**: щоденні або щотижневі скани вибраних репозиторіїв через launchd, тож вони працюють і тоді, коли застосунок закритий. Після планового скану з'являється сповіщення.
- **Зручно для Free-плану**: локальна оцінка використаних цього місяця тестів Open Source і Code відносно лімітів Free-плану, і один агрегований Maven-тест на багатомодульний репозиторій замість тесту на кожен `pom.xml`.
- **Menu bar**: підсумок одним поглядом і кнопка "Scan all now".

## Вимоги

- macOS 14 Sonoma або новіша, Apple Silicon.
- Обліковий запис Snyk. [Free-план](https://snyk.io/plans/) підходить.
- Інструменти збірки, потрібні вашим проєктам для розв'язання залежностей (Maven для `pom.xml`, Gradle, Node.js тощо). Snyk запускає їх, щоб прочитати дерево залежностей. Встановлювати їх самому не треба: налаштування і **Settings > Tools** показують, чого не вистачає, і встановлюють це. Те, що в вас уже є, використовується як є.

## Встановлення

1. Завантажте `SnykDesk-<version>.zip` з [Releases](https://github.com/bodco/snyk-desk/releases).
2. Розпакуйте і перемістіть **Snyk Desk** у Applications.
3. Застосунок підписаний ad hoc і не нотаризований. Першого разу клацніть правою кнопкою і виберіть **Open**, або виконайте:
   ```
   xattr -dr com.apple.quarantine "/Applications/Snyk Desk.app"
   ```

## Як це працює

```
Snyk Desk.app ──пише──> <папка запускача>/snyk-desk-scan.sh ──запускає──> snyk test / code test / monitor
      │                            ▲                                              │
      │                            └── агент launchd (розклад)                    │
      └──читає── <папка результатів репо>/<timestamp>/ <───────────────пише────────┘
```

- **Запускач.** Застосунок створює один shell-скрипт `snyk-desk-scan.sh` у вибраній папці і переписує його щоразу, коли змінюються налаштування. І застосунок, і розклад запускають саме його, тож ручні й планові скани поводяться однаково. Його можна запустити й самому:
  ```
  ./snyk-desk-scan.sh                 # репозиторії, що є в розкладі
  ./snyk-desk-scan.sh <repo-id> ...   # конкретні репозиторії (id є в config.json)
  ```
- **Результати.** Кожен скан пише сирий вивід Snyk (`deps.json`, `code.json` у форматі SARIF), логи і коди виходу в `<папка результатів>/<timestamp>/`. За замовчуванням папка результатів репозиторію це `<папка запускача>/<проєкт>/<назва папки репозиторію>/`; якщо два репозиторії одного проєкту мають однакову назву папки, до неї додається короткий суфікс, щоб скани не змішувались. Якщо змінити проєкт репозиторію, його дефолтна папка теж зміниться, а попередні скани лишаться в старій. У Settings або на сторінці репозиторію можна вибрати іншу папку, повернутись до дефолтної або відкрити її у Finder. У ваші репозиторії нічого не пишеться, якщо ви самі не виберете папку всередині одного з них.
- **Налаштування** лежать у `~/Library/Application Support/SnykDesk/config.json`.
- **Розклад.** Застосунок пише `~/Library/LaunchAgents/pm.bodco.snykdesk.scan.plist` і завантажує його через `launchctl`. Якщо Mac у цей час спить, launchd запустить скан після пробудження. Вимкнення розкладу видаляє агента.
- **Вхід.** "Log in to Snyk" запускає `snyk auth`, що відкриває браузер. CLI зберігає токен у власному конфігу. Snyk Desk ніколи не читає, не показує і не зберігає його.
- **Інструменти збірки.** Налаштування і Settings > Tools перевіряють кожен інструмент у PATH і в `~/Library/Application Support/SnykDesk/tools`. Відсутні завантажуються з офіційних сайтів (Temurin JDK 21, Apache Maven, Gradle, Node.js, Go), розпаковуються туди й додаються до PATH і `JAVA_HOME` запускача. Ваші власні встановлення мають пріоритет. Xcode Command Line Tools (git, Python 3, Swift) можна отримати лише з інсталятора Apple, тому застосунок відкриває його й чекає. Перед кожним скан залежностей запускач перевіряє, що інструмент збірки репозиторію працює, а якщо ні, скан пише про це простими словами замість загальної помилки `SNYK-CLI-0000`.
- **Встановлення CLI.** Якщо `snyk` немає в PATH, застосунок завантажує standalone-бінарник з `downloads.snyk.io` у `~/Library/Application Support/SnykDesk/bin`. Наявне встановлення (npm, Homebrew) використовується як є.

## Ліміти Free-плану

Free-план Snyk має місячні ліміти тестів для кожного продукту (на момент написання: 200 Open Source, 100 Code, 100 Container, 300 IaC). Тести публічних репозиторіїв не враховуються. Коли ліміт вичерпано, тести зупиняються до наступного місяця. Актуальні цифри дивіться на [snyk.io/plans](https://snyk.io/plans/).

Як Snyk Desk витрачає тести, наскільки це можна визначити:

| Крок | Продукт | Приблизно |
|---|---|---|
| Скан залежностей | Open Source | один тест на кожен знайдений маніфест; один на репозиторій для багатомодульного Maven |
| Знімок (`monitor`) | Open Source | один на маніфест |
| Скан коду | Code | один на репозиторій |

Шкали використання в застосунку рахують лише скани, запущені цим застосунком. Офіційний лічильник веде Snyk у вашому обліковому записі.

## Приватність

- Скан залежностей надсилає в Snyk список пакетів і версій, а не вихідний код.
- **Скан коду завантажує вихідний код** у Snyk для аналізу. Вимкніть **Code** для репозиторію, якщо для нього це заборонено.
- Знімок (`monitor`) зберігає дерево залежностей у вашому обліковому записі Snyk, щоб Snyk повідомляв про нові вразливості.

## Збірка з вихідного коду

```
git clone https://github.com/bodco/snyk-desk.git
cd snyk-desk
swift test
scripts/make-app.sh 0.1.0    # dist/Snyk Desk.app і dist/SnykDesk-0.1.0.zip
```

Потрібен Xcode 16 або новіший (Swift 5.10+). Основна логіка (`Sources/SnykDeskCore`) покрита юніт-тестами, інтерфейс лежить у `Sources/SnykDesk`.
